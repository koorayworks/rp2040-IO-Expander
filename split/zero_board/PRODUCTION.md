# Zero側基板 発注用データ

- `gerber/` + `zero_board_gerber.zip`: ガーバー一式（4層、Protel拡張子）とドリル（PTH/NPTH別ファイル）
- `zero_board_bom_jlc.csv`: JLC PCBA用BOM（Comment/Designator/Footprint/LCSC）
- `zero_board_cpl_jlc.csv`: 部品配置（座標は基板左下原点・Y上向き、FH35Cはパッド中心で補正済み）

## バリエーション
- 本データは **表実装版**（FH35C = J3・表面）。裏実装版は BOM/CPL の J3 を J4 に読み替える
  （基板自体は両面にフットプリントがあり、実装しない側はパッドだけ残る）
- J1 は Zero 端子パッド（部品なし）のため BOM/CPL に含めない

## 改訂（2026-11-13 夜・外部精査を受けて再出力）
- **D1 (WS2812B-2020) のパッド割当ミスを修正**: 生成スクリプトが 5050 版の
  ピン配置で割当てていた。正しくは 1=DO（無接続）、2=GND、3=DI (STATUS_LED)、
  4=VDD (3V3)（データシート V1.3）。配線も組み替え済み、DRC は修正前と
  同条件で新規違反ゼロ・未接続0・ショート0
- **D1 は BOM で WS2812B-2020-V6 を指定**（V6 は 3.3〜5.3V 対応。素の
  WS2812B-2020 は 3.7〜5.3V で 3.3V 駆動は仕様外）

## 改訂（2026-11-16・FH35C パッド鏡像化）
- **J3/J4 の信号パッド配置を左右鏡像化**（組み立て時の全チャンネル
  反転への対策。経緯と検証は `split/FFC_PINMAP_30P.md` 冒頭の
  「2026-11-16 解決」を参照）。全面再配線＋GND プレーン分断の
  手仕上げを実施し、DRC は未接続0・ショート0（他は従来同等の
  軽微カテゴリのみ）。Gerber／zip は再出力済み、BOM/CPL は
  部品配置不変のため差分なし

## 改訂（2026-11-16・独立監査対応）
- **USB_VBUS を VSYS に統合**: 監査で「USB-C の VBUS が VSYS に
  未接続（仕様の統合凍結に違反）」と判明。VBUS パッドと U1.5 の
  ネットを VSYS へ付け替え、B.Cu トラック1本でブリッジ。
  VSYS 全8パッドが単一接続成分であることを確認済み。
  DRC は未接続0・ショート0（総数・カテゴリとも修正前と同数）。
  Gerber／zip は再出力済み、BOM/CPL は差分なし

## 発注前の残確認
- LCSC番号が未記入の部品（WS2812B-2020-V6、0402の5.1k/100nF）は発注時に照合すること
- FH35C のピン1向きは図面・3Dモデル・独立トレースで解決済み。初回実物では導通確認を最終確認として行う

## 監査ラウンド3対応（2026-11-16）

- **線幅**: 0.1mm 未満だった6件（GPIO8×4・RESET×2、いずれも B.Cu）を
  0.1mm へ拡幅。DRC 66→60（track_width 0）。控え: backup/pre_widthfix_20261116.kicad_pcb
- **基板端クリアランス**: 内層トラック10件（GPIO14 In1.Cu×4・GPIO9 In2.Cu×6、
  南端際で最小 0.060mm だった）を頂点移動のみで端から 0.15mm 以上へ。
  DRC 60→50。残る copper_edge_clearance 16件は全て J2（USB-C）のパッドが
  北端に接する設計どおりのもの。控え: backup/pre_edgefix_20261116.kicad_pcb
  - 注記: GPIO9 の底面ランは、端 0.15mm と J1.13 パッドとの clearance
    0.1mm を両立できる帯が約0.003mm 幅しかない箇所で、採用値では両側とも
    余裕がほぼない（端側 0.1510／パッド側 約0.101）。DRC は通過しているが
    製造ばらつき的にはタイトな1点として認識しておくこと
- どちらも独立検証（結論を渡さず）で全項目「一致」。Gerber 再出力済み、
  BOM/CPL は不変
