## 残り3ペアの切り分け（手仕上げ・種付けとも試行済み）

- GPIO4 (U1.23): パッド北側ポケットは GPIO3/GPIO5 の先端ビアで満員。
  ラウンド17で配置ビア (8.58,15.98)＋Fスタブの種付けが効き、
  その基板では完結した（代わりに他ネットが入れ替わりで落ちた）。

  ラウンド17で完結を確認。手仕上げは GPIO14 のビア・GPIO2 の
  B斜め・下辺パッド矩形に四方を塞がれる。
- GPIO3 (J2): スタブ端 (7.8,19.3) は配置銅で四方封鎖
  （W: GPIO13 潜りビア (7.55,18.95)、E: GPIO9 ビア (8.4,18.98) と

  (7.85,21.15)、W追加: GND の B スタブと GPIO15 のスタブ）。
  種付け案5つ全滅。**直すなら配置変更が要る**: GPIO13 の潜りビアを
  動かしてスタブ端の扇を空けるのが本命。

## 2026-11-12 夜の到達点と教訓

- 最良基板は r30（未接続3ペア: GPIO1・GPIO9・USB_D+）。
  ただし USB_D+ は配置側の南アンカー（I2 を南帯へ回す種付け）で
  恒常的に閉じることが r33〜35 で実証済み。次ラウンドは現行配置
  （placement_v31_round35seeds、全種付け入り）から引けば
  実質の残りは GPIO1・GPIO9 中心になる見込み
- 「ネット反転」の正体: 同一層で他ネットの銅に物理的に重なる／
  かすめる種付け要素は、保存時の接続性マージで相手ネットに
  取り込まれる。対策は幾何学的に離すこと。検証は DRC でなく
  DSN テキストで対象 wire の (net ...) を直接見る
- dump_net.py は基板パスをハードコードしていた（修正済み:
  環境変数 BOARD_PATH で指定）。ツールがどのファイルを読むか
  必ず確認すること
- J2.14（GPIO9）には配置スタブ自体が無かった（手置き漏れ）。
  r32 で stub (9.6,19.925)->(9.6,19.45) B を追加済み
- ラウンドごとの分散が大きい（3〜11）。種付けしたネットは
  概ね保持されるが、未種付けネットが回転的に割れる。
  全接続には「あと1〜2ネット分の種付け」＋「当たり回」が必要

## ラウンド36〜45（2026-11-13、軽い土台への方針転換）

未接続1ペアだった r25 の配置（placement_v20）を土台に戻し、
実績のある修正だけを配置グラフト（graft_rXX_seeds.py）で
移植する軽量路線に切り替えた。

- r36: r35 の同一 DSN 再実行で完全同一結果（8ペア）。
  **Freerouting は決定的。配置を変えずに再実行しても無駄**
- r37: 7ペア（全積み土台の最終）/ r38: 8 / r39: 10（悪化）
- r40（軽い土台: r25＋GPIO15 アンカー＋USB_D+ 南北アンカー）:
  7ペア {EX5×2, GPIO6, GPIO7, GPIO12, GPIO26, GPIO28}。
  常習の GPIO1・GPIO9 が両方完結、GPIO15・USB_D+ も維持
- r41（＋EX5 I1 スタブ、GPIO7 ダイブ、GPIO26 J2 スタブ、
  GPIO6 ジョグ）: **5ペア** {EX5, GPIO6, GPIO10, GPIO27, GPIO28}。
  GPIO7・GPIO26 完結
  - **訂正**: GPIO7 の「種付け」ビア (9.9,14.6) は GPIO2 の
    ビアと同位置で、保存時に GPIO2 へ取り込まれて実在しない
    （v36/v38 の dump で確認）。GPIO7 の完結は種付けでなく回転
  - ランタイム再起動で2回中断（パス16付近）。DSN 控えから再実行
- r42（＋EX5 I1 延長、GPIO6 I1 アンカー、GPIO27/GPIO28

- r43（＋GPIO5 I1、GPIO6 I1 延長、GPIO10 I2 南下、GPIO14
  J2 スタブ、GPIO28 東延長）: 8件／6ネット。GPIO1・GPIO5・
  GPIO10・GPIO28 完結
- r44（＋GPIO6 F ブリッジ、GPIO8 両スタブ、GPIO11、GPIO12）:
  **13件に悪化**（USB_D+ と 3V3_BAT まで割れた）
  - 種同士の衝突事故: GPIO6 F ブリッジと GPIO8 J1 スタブ
    （SE 向き）が交差してショート。種は土台基板に対してだけでなく
    **種同士でも検証**すること（GPIO8 は SW 向きに直して解消）

- **手仕上げ hf41a**: r41 配線済み基板に EX5 の不足 1.28mm
  （I1 (12.6,25.8)->(13.88,25.8)）を1本追加 → **4ペア**
  {GPIO6, GPIO10, GPIO27, GPIO28}、clearance 0、

  - 注意: この基板は LoadBoard/SaveBoard を経たため、ファイル内
    接続性では SJ1（FFC2_1↔3V3）が同一ネットにマージされ、
    DRC の shorting は5件表示になる（銅形状は不変・意図どおり）

### hf41a の手仕上げ限界の検証（2026-11-13 10:5x）

hf41a の残り4ペアについて、既存銅を一切動かさない手仕上げの
可否をグリッド探索（A*、0.2mm 格子・8方向・4層・ビア40 遷移、
検証は checker の実クリアランス）で網羅的に調べた。

- **4ペアとも経路なし**: GPIO6／GPIO10／GPIO27／GPIO28
- 探索器の妥当性は対照実験で確認済み: r41 基板（手仕上げ前）に
  同じ探索をかけると、実際に閉じた EX5 の経路
  （I1 (13.88,25.74)->(12.6,25.8)）を即座に再発見する
- 個別の手作業試行とも一致（GPIO27 の J2.6 北スタブは
  GPIO14 の B 配線に 0.02mm で抵触、SE 向きスタブだけは
  通るがその先が全方向塞がれている、等）
- 結論: **hf41a における手仕上げの天井は4ペア**。これ以上は
  既存銅の局所引き直し（例: GPIO14 の B ウェブを動かして
  GPIO27 の逃げを作る）か、配置変更が要る

### 現在の到達点（2026-11-13 10:1x）
